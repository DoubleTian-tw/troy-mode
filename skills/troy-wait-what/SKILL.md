# Troy Wait What

將上一段 AI 回答講清楚，而不是新增研究、做決策或執行工作。

## 範圍

- 僅在使用者明確觸發時執行；不要因為你認為回答可能難懂就自行觸發。
- 預設重述緊鄰的上一段 assistant 回答。若使用者提供文字或指定段落，以其指定內容為準。若沒有可重述內容，請簡短詢問要解釋哪一段。
- 不修改檔案、不執行程式、不查詢網路，也不自動呼叫 `troy-research`、`troy-grilling` 或其他 skill。

## 取得脈絡

1. 若存在，讀取 `~/.agents/CONTEXT.md`。它只定義個人共用的溝通與安全原則，不能覆蓋使用者當前指示或專案事實。
2. 判斷待重述內容是否涉及專案脈絡。出現 repo 或功能名稱、檔案路徑、內部術語、PRD／SA／SD／change，或使用者明說「依目前專案」時，視為涉及專案脈絡。
3. 涉及專案脈絡時，從目前工作目錄的 repo 根目錄讀取 `CONTEXT-MAP.md`。只讀取 map 明確列出的 context 檔案；不得掃描整個 repo，也不得讀取機密或敏感檔案。
4. 找不到 map、map 指向的檔案不存在、無法讀取，或 context 無法回答該術語時，照對話內容重述，並標示脈絡不足。
5. 多個 context 有衝突時，不自行猜測。以範圍較小且較接近問題的 context 優先，並列出衝突來源與對解釋的影響。

## 重述規則

- 使用台灣繁體中文、熟悉的日常用語與短句。首次出現必要技術名詞時，可保留英文並附短中文說明。
- 先說這段話的目的，再說它與目前工作的關係。不要逐字改寫或加入未被支持的事實。
- 將前提、推論與未確定事項分開說明。發現需要使用者選擇時，只指出可使用 `troy-grilling`；發現需要外部事實時，只指出可使用 `troy-research`。

## 範例

使用者說：`$troy-wait-what 我不懂剛剛為什麼先 research 再 grilling。`

回答應先將「研究用來查證外部事實；盤問用來選擇偏好與取捨」說成白話，再指出該情況的下一步；不要在此 skill 中直接開始研究或盤問。
