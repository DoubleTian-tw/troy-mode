# Troy Research

將外部可驗證的不確定性轉化為簡短、可追溯的研究筆記。研究旨在確立事實與限制條件，而非替使用者做出產品或商業決策。

## 研究前準備

1. 定義問題、該問題所影響的決策，以及能回答該問題的來源類型。將範圍收斂至單篇筆記即可回答的程度。
2. 在建立筆記前確定存放目的地：
    - 若使用者已有提供路徑，請直接使用。
    - 否則，檢視專案中現有的文檔與筆記慣例。優先尋找 `docs/`、`notes/`、`research/`、特定功能文檔以及存放庫說明。絕不檢視機密或敏感檔案。
    - 列出最多三個合理的位置，標註建議選項，並等待使用者選擇。若專案無既有慣例，提供一個合理的預設路徑，切勿在未告知的情況下自行建立全新的文檔結構。
3. 若該不確定性屬於商業優先級、政策抉擇或任何無法透過客觀資料定案的偏好，跳過研究流程，改用現有的 `grilling` 工作流與使用者進行釐清。

## 研究工作流程

確認輸出路徑後，若環境支援 Agent 委派，將資料來源探索與證據收集委派給後台 Agent（background agent）。提供其研究問題、限制條件與所需的來源標準。委派必須回傳：

- 候選結論，且每項主張皆附帶直接來源；
- 相關版本、日期與適用範圍限制；
- 矛盾之處、未知事項以及需要在本機測試的項目；以及
- 仍取決於使用者決策的選項。

只要存在一手來源（primary sources），務必優先採用：官方文檔、規格標準、原始碼、第一方 API 參考資料、正式公告或原始研究報告。針對具時效性的主題，需驗證當前資訊並記錄查閱日期。切勿將搜尋摘要片段（search snippets）或二手機構整理視為證據。

撰寫前請先檢視研究發現。僅在引用的來源能直接支持時，方可將陳述標記為事實。綜合歸納之處應標記為推論。切勿以看似合理的猜測來填補空白。

## 撰寫筆記

複製 [assets/template.md](assets/template.md) 至已確認的目的地，且僅填寫重要的章節。在每項支持的主張旁保留直接連結。簡明扼要的筆記優於巨細靡遺的資料堆砌。

若研究後仍有實質抉擇尚未定案，請將其記錄在 **需要使用者確認** 區塊下，並列出可行選項、有證據支持的影響，以及所需的決策。接著若有 `troy-grilling` 則調用它；否則請向使用者提出聚焦且中立的問題。切勿將未決定的事項包裝為研究結論。

## 邊界原則

- 切勿僅因為研究顯示了某個方向，就逕自修改產品規格、原始碼或設定檔。
- 在使用者提供或選定目的地之前，切勿建立研究筆記。
- 切勿以此工作流取代專案既有的需求討論流程。在 `discuss-spec` 中，僅將此工作流用於需要外部證據的分支。
